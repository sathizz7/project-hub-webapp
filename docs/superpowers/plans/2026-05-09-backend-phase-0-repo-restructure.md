# Backend Phase 0 — Repo Restructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reorganize the existing single-app repo into a monorepo with `frontend/` (current Next.js app, untouched) and an empty `backend/` skeleton, ready for Phase 1 to start scaffolding FastAPI.

**Architecture:** Pure `git mv` exercise — preserves history, no functional change. The frontend continues to build, run, and pass tests from its new location. `backend/` exists as an empty directory with a `.gitkeep` so future phases have a target to drop into. Root `README.md` becomes a monorepo overview pointing at each app. A `docs/migration-mapping.md` skeleton is created to track route migration progress through later phases.

**Tech Stack:** Next.js 16 (existing — moves only), git, bash. No new dependencies.

**Spec source:** `docs/superpowers/specs/2026-05-09-projecthub-fastapi-backend-design.md` — Section 1 (repo layout), Section 6 Phase 0.

**Branch:** `feature/backend-phase-0-restructure` (cut from `feature/ui-polish`)

---

## Decisions locked

| Topic | Decision | Why |
|---|---|---|
| Use `git mv` (not `mv` + `git add`) | preserve git history per file | future blame/log on moved files keeps working |
| `.env` and `.env.local` | physically move (not `git mv` — they're gitignored) | files exist on disk but aren't tracked; `mv` is fine |
| `node_modules` and `.next` | delete from root after move; reinstall in `frontend/` | cleaner than physical move; both are gitignored regenerable artifacts |
| `dev.db` | `git mv` into `frontend/` | currently tracked; will be deleted in Phase 7 anyway |
| Root `README.md` | rewrite as monorepo overview; old content goes to `frontend/README.md` | both apps deserve their own quickstart |
| `DEVELOPMENT_GUIDE.md` and `PRODUCT_SPEC.md` | `git mv` into `docs/` | they're documentation, belong in shared docs/ |
| `.gitignore` | stays at root; patterns updated to scope to `frontend/` | one `.gitignore` covers both apps |
| Empty `backend/` | create with a `.gitkeep` placeholder | git tracks empty dirs only via a placeholder file |
